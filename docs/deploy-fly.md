# Fly.io: book.ayudenko.by

Подготовленная конфигурация: приложение `book-ayudenko`, регион `fra`, одна Machine shared CPU / 512 MiB, постоянный volume `book_data` размером 1 GiB. Имя приложения ещё не проверено на доступность. `APP_ORIGIN=https://book.ayudenko.by`, база `/data/quiet-chapter.sqlite`. Секреты для текущей cookie-авторизации не нужны: сессии хранятся в SQLite.

## Первый запуск

В терминале с доступом к Fly.io:

```sh
cd /Users/a.yudenko/Documents/Self/book-writer
fly auth whoami
fly apps create book-ayudenko
fly config validate
npm run deploy
fly status
fly volumes list
fly ips list
fly certs add book.ayudenko.by
```

Если вход не выполнен, используйте `fly auth login`. При создании выберите свою организацию. Если приложение уже существует в вашей организации, пропустите создание. Не используйте чужое существующее приложение. При занятости имени выберите новое и измените `app` в `fly.toml`.

Деплой использует remote builder и `--ha=false`. При первом деплое Fly создаёт volume по `mounts.initial_size`; проверьте, что есть ровно одна Machine с подключённым `book_data`. Не увеличивайте число Machines: SQLite не реплицируется. Стратегия immediate предполагает короткий простой при обновлении единственного экземпляра. Автоостановка включена, первый запрос после простоя запускает Machine.

Если публичных IP нет, выделите отсутствующие адреса перед настройкой DNS:

```sh
fly ips allocate-v4 --shared
fly ips allocate-v6
```

Команды выделения адресов нужны только для отсутствующих типов адресов. Приложение, volume и snapshots расходуют ресурсы аккаунта Fly.io; стоимость определяется его тарифами.

## DNS и TLS

`fly certs add book.ayudenko.by` выводит необходимые DNS-записи. Добавьте **именно возвращённые значения** у провайдера DNS для `ayudenko.by`: A/AAAA для `book` или предложенный Fly CNAME и записи подтверждения. IP и validation targets заранее неизвестны. Не заменяйте DNS остальных поддоменов.

Если DNS в Cloudflare, для прямого подключения к Fly используйте DNS only. Текущая конфигурация ожидает прямой клиентский трафик через Fly Proxy. После обновления DNS:

```sh
fly certs check book.ayudenko.by
fly checks list
npm run smoke
```

`smoke` проверяет HTTPS главной страницы, доступность SQLite через `/api/health` и запрет чтения библиотеки без входа. Не создаёт аккаунты и не меняет рукописи. В браузере отдельно проверьте регистрацию, создание книги, сохранение и повторный вход. Если работает только адрес `*.fly.dev`, вход с него будет отклоняться: разрешённый Origin — целевой домен.

## Что попадает в образ

Docker выполняет синтаксические проверки и тесты на Node 24, затем копирует только приложение. `.dockerignore` не передаёт локальные SQLite, `.env`, резервные копии или пользовательские данные в удалённый builder. После подготовки прав volume процесс работает от пользователя `node`, не root.

Впервые опубликованная база пустая. Для переноса старых книг экспортируйте JSON на localhost, создайте аккаунт на домене и импортируйте копию там. `localStorage` localhost не доступен с нового домена. Этот способ не переносит старые пароли и сессии.

## Обновление и резервные копии

```sh
npm run deploy
npm run smoke
```

Миграция схемы происходит при открытии SQLite в приложении. `release_command` не используется, поскольку отдельная release Machine не имеет доступа к volume основного приложения.

Включены ежедневные volume snapshots с хранением 14 дней. Это не замена отдельной резервной копии. Для согласованного снимка SQLite:

```sh
fly ssh console -C 'node /app/scripts/backup.mjs'
```

Скачайте файл из пути, напечатанного командой, через `fly ssh sftp get <remote-path> <local-path>` и храните вне volume. Команда не запускается по расписанию. При остановленной Machine сначала откройте сайт, чтобы она запустилась.

Для восстановления остановите приложение, восстановите volume из выбранного снимка либо восстановите SQLite из согласованной копии, удалив только старые WAL/SHM этой базы. Проверьте владельца базы uid/gid `1000:1000`. Не удаляйте рабочий volume до проверки восстановленного.

## Прокси и безопасность

`TRUST_FLY_PROXY=true` применяется только при наличии выставленного Fly `FLY_APP_NAME`. Сервер использует валидный `Fly-Client-IP` для лимитов входа; `X-Forwarded-For` игнорируется. Включать эту настройку можно только за доверенным Fly Proxy, не при прямом публичном доступе к порту Node. Не выставляйте порт 4000 как отдельный публичный TCP-сервис. Частная сеть организации также должна оставаться доверенной.

## Статус подготовки

Локальные тесты выполняются без TCP. Создание приложения, remote build, TLS и живые проверки ещё не выполнены: среда агента запретила Fly CLI запись служебного файла в `~/.fly`, а Docker API недоступен из песочницы. Эти ошибки не означают отсутствие авторизации в Fly — проверить её не удалось.
