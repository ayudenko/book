# API «Тихой главы»

Источник контракта для реализации: `openapi.json`. API и интерфейс обслуживаются одним origin.

- `POST /api/auth/register`: email и пароль (12–128 символов); создаёт аккаунт с пустой библиотекой, выдаёт HttpOnly cookie сессии.
- `POST /api/auth/login`: проверяет пароль, создаёт новую сессию.
- `GET /api/auth/me`: текущий пользователь или 401.
- `POST /api/auth/logout`: отзывает текущую сессию, очищает cookie, 204.
- `GET /api/library`: библиотека только текущего пользователя и целочисленная `revision`.
- `PUT /api/library`: `{revision, library}`; атомарно сохраняет книги, архив, главы, заметки, географию и версии. Возвращает новую revision. При несовпадении revision — 409 без изменений.

Библиотека — единый агрегат текущего интерфейса. Это уменьшает риск частичного сохранения связанных данных, но передаёт всю библиотеку при изменении и блокирует конфликтующие изменения даже в разных книгах. Для большой библиотеки следующим шагом будет отдельный API книг; текущий лимит JSON-запроса — 20 МиБ, до 100 книг. Сервер определяет владельца исключительно по сессии; userId в URL/теле не используется. Оба запроса `/api/library` требуют заголовок `X-Account-ID` с id из `/api/auth/me`: несовпадение с владельцем сессии возвращает 409 `account_changed`, чтобы старая вкладка не перезаписала данные после входа в другой аккаунт.

Все изменяющие запросы требуют точного `Origin`, совпадающего с `APP_ORIGIN`, и `Content-Type: application/json`. Это включает вход и регистрацию, исключая login-CSRF. CORS для сторонних origin не включён. При HTTPS cookie имеет Secure, HttpOnly, SameSite=Lax, Path=/; срок сессии — 14 суток. Токены сессий хранятся в базе только как SHA-256, пароли — scrypt с уникальной солью.

Ошибки: `{error:{code,message}}`; 400 невалидные данные, 401 нет сессии/неверный пароль, 403 неподходящий Origin, 409 занятый email/конфликт версии, 413 превышение размера, 415 не JSON, 429 лимит входов/регистраций, 500 внутренняя ошибка. GET и ответы авторизации запрещают кеширование.

Postman CLI в среде разработки отсутствует. Контракт хранится локально и может импортироваться в Postman. Проверки выполняются Node test runner через настоящий обработчик Request/Response с временной SQLite; они не требуют открытия TCP-порта и не заменяют браузерную проверку.

Книга может содержать необязательный `outline`: режим `free`/`chapters`, общий замысел `summary` и упорядоченный список `items` (до 1000). Пункт содержит `id`, `title`, `body`, `chapterId` (null для свободного плана). Ссылки на главы должны существовать и не повторяться. При удалении главы клиент переносит её план в свободные пункты, сохраняя содержание. Отсутствие поля в старой книге означает пустой план; отдельная миграция базы не нужна. План не входит в снимки текста глав, но входит в JSON-копию книги и сохраняется атомарно вместе с библиотекой.

`GET /api/health` — публичная проверка доступности процесса и чтения SQLite, ответ `200 {"status":"ok"}` или 500 без подробностей базы. Используется Fly health checks. Production origin: `https://book.ayudenko.by`.
