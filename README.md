# Тихая глава

Репозиторий: https://github.com/ayudenko/book · Сайт: https://book.ayudenko.by

Рабочее пространство автора с личным аккаунтом и серверным хранением книг. Node.js обслуживает интерфейс и API, SQLite хранит пользователей, сессии и рукописи на диске. Внешние сервисы и npm-зависимости не требуются.

## Запуск

Нужен **Node.js 24 или новее** со встроенным `node:sqlite` (Node может выводить предупреждение об экспериментальном API).

```sh
npm start
```

Откройте **http://localhost:4000**, нажмите «Нет аккаунта? Зарегистрироваться», укажите email и пароль от 12 до 128 символов. Новый аккаунт получает пустую библиотеку. После входа можно создавать книги или импортировать существующие.

Если уже запущен старый сервер, остановите его и запустите заново: одной перезагрузки страницы недостаточно для подключения нового API.

По умолчанию база находится в `data/quiet-chapter.sqlite`; её таблицы создаются при запуске. Перезапуск приложения не удаляет данные. Порт остаётся 4000.

Конфигурация — переменные окружения из `.env.example`. Файл `.env` автоматически не читается; при необходимости запускайте `node --env-file=.env server.mjs`.

| Переменная | Значение по умолчанию |
| --- | --- |
| `PORT` | `4000` |
| `HOST` | `127.0.0.1` |
| `APP_ORIGIN` | `http://localhost:<PORT>` |
| `DATABASE_PATH` | `./data/quiet-chapter.sqlite` |
| `BACKUP_DIR` | `./data/backups` (для команды резервного копирования) |

`APP_ORIGIN` должен точно совпадать с адресом в браузере, включая схему и порт, без завершающего `/`. Например, `localhost` и `127.0.0.1` — разные origin.

## Возможности

- Библиотека книг — стартовый экран, разделы «В работе» и «Архив».
- Создание пустой книги с первой главой; отдельные текст, заметки, персонажи, цель и история для каждой книги.
- Архивация без потери данных и возврат в работу. Удаление всей книги с подтверждением её названия, включая возможность удалить последнюю книгу.
- Переход из редактора через «Все книги». Резервную копию можно скачать из карточки любой книги, в том числе архивной.
- Главы: создание, переименование, удаление с подтверждением.
- «План книги» в боковой панели и кнопка «План» сверху: общий замысел, свободные пункты без глав (добавление, редактирование, перестановка, удаление) и отдельные описания существующих глав. Оба режима сохраняют содержание при переключении. При удалении главы её план становится свободным пунктом. План сохраняется на сервере и в JSON-копиях; в TXT-экспорт рукописи и историю текста глав он не входит. До 1000 пунктов, по 100 тыс. символов в описании и общем замысле. Старые книги без плана поддерживаются.
- Редактор: отступ первой строки абзаца, жирный, курсив, подчёркивание, зачёркивание, заголовки, цитаты, отмена ввода. По умолчанию текст выровнен по ширине. Выравнивание по левому краю, по центру, по правому краю и по ширине применяется к текущему абзацу или всем выделенным абзацам. Для выделенного текста есть меню «Выделение»: жёлтый, зелёный, голубой, розовый и «Убрать цвет». Выравнивание, зачёркивание и цвет сохраняются в рукописи, истории и JSON-копиях. Заголовки и цитаты отображаются без абзацного отступа; Shift+Enter переносит строку внутри текущего абзаца.
- Автосохранение после ввода. До 60 снимков на главу: через 12 секунд покоя, при переключении, уходе со страницы или вручную.
- Просмотр и восстановление версий с сохранением текущего черновика.
- Заметки к книге, карточки персонажей, пометки к выделенному фрагменту. Пометки сохраняют цитату; они не привязаны к меняющимся позициям текста и не подсвечиваются внутри рукописи.
- Вкладка «География»: создание, редактирование и удаление карточек мест. У объекта есть название, тип (город, страна, река и другие, включая свой вариант) и описание. География относится ко всей книге, сохраняется при архивации и входит в JSON-копию; старые копии без географии также поддерживаются.
- Цель по общему объёму книги, счётчик слов/знаков, оценка времени чтения.
- Режим фокуса (выход — Escape), сохранение версии — Ctrl/Cmd+S.
- Экспорт выбранной книги в TXT. Полная JSON-копия книги с заметками и историей, импорт с проверкой структуры. Импорт добавляет отдельную книгу и не заменяет существующие.
- Адаптивный интерфейс для компьютера и телефона.

## Перенос старых книг

После входа в библиотеке появляется кнопка **«Перенести книги из этого браузера в аккаунт»**, если найдено прежнее хранилище `quiet-chapter:v1`. Диалог показывает аккаунт-получатель. Переносятся все книги, включая архив, главы, заметки, героев, географию и историю. Исходная локальная библиотека не удаляется. Кнопка скрывается после подтверждённого сервером сохранения.

Локальное хранилище привязано к origin. Если раньше писали на другом порту, сначала экспортируйте JSON-копию там, а затем используйте «Открыть копию» на новом адресе. Старые JSON-копии одной книги поддерживаются. Импорт добавляет новые книги и не заменяет существующие; полная JSON-копия библиотеки также поддерживается.

## Сохранение и конфликты

- У каждого аккаунта собственная библиотека. Владелец определяется серверной сессией, не параметрами клиента.
- Автосохранение на сервер запускается после 700 мс паузы. Подпись «Сохранено на сервере» появляется только после успешного ответа API.
- До отправки браузер сохраняет резервный черновик под ключом текущего пользователя. При потере сети доступны повторная отправка и скачивание всей библиотеки. Если браузер не даёт записать локальную копию, приложение предупреждает и продолжает серверное сохранение.
- При входе незавершённое сохранение повторяется, если серверная версия не изменилась. При конфликте черновик не перезаписывается автоматически: сначала скачайте локальную библиотеку, затем загрузите серверную и импортируйте нужные книги из копии.
- При одновременном редактировании сервер проверяет номер версии и возвращает 409 для устаревшего сохранения. Разные вкладки одного браузера дополнительно останавливают запись при обнаружении внешнего изменения. Совместное редактирование в реальном времени не реализовано.
- Выход выполняется после завершения сохранения и отзывает текущую сессию. Локальная копия аккаунта удаляется при выходе; старые данные до миграции сохраняются. Пароли и токены сессий не хранятся в `localStorage`.

Сейчас библиотека сохраняется одним атомарным JSON-агрегатом: до 100 книг, 500 глав и 2000 заметок на книгу, 60 версий на главу, не более 20 МиБ на запрос. Лимит браузерного хранилища может быть ниже. Текст главы/версии ограничен 2 млн символов, заметки/цитаты — 100 тыс. Для очень больших библиотек потребуется сохранение отдельных книг/глав.

TXT экспортирует рукопись без оформления. JSON содержит поддерживаемое оформление и материалы книги. Вставка из буфера — обычный текст; при загрузке HTML очищается по разрешённому списку тегов.

## Авторизация и размещение

Пароли хешируются `scrypt` с индивидуальной солью. В базе сохраняются SHA-256 хеши случайных токенов сессий, не сами токены. Сессии действуют 14 суток. Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/`; для HTTPS добавляется `Secure`. Изменяющие запросы требуют совпадающего `Origin` и JSON. Вход и регистрация ограничены 20 попытками за 15 минут по IP и email; счётчики сохраняются при перезапуске.

Для размещения нужен **постоянный сервер Node.js и диск**, а не статический хостинг. Запускайте за HTTPS reverse proxy с `NODE_ENV=production` и `APP_ORIGIN=https://ваш-домен`. В production сервер откажется стартовать с HTTP origin. `HOST=0.0.0.0` нужен только при доступе из контейнера или другой машины. Приложение не доверяет `X-Forwarded-For`: за reverse proxy лимит IP общий для его подключения; при масштабировании нужна настроенная политика доверенных прокси. База предназначена для одного экземпляра приложения на локальном диске, не сетевой файловой системе.

Эта версия не включает подтверждение email, восстановление/смену пароля, OAuth, совместный доступ и автоматические резервные копии. Email используется как имя входа, письма не отправляются. До открытого запуска стоит подключить восстановление пароля и эксплуатационный мониторинг.

База не зашифрована на диске: доступ к серверным файлам необходимо ограничить. Данные и `.env` исключены из Git. Google Fonts используются только для шрифтов; без сети есть системные замены.

## Резервное копирование сервера

```sh
npm run db:backup
```

Команда использует SQLite Backup API и создаёт согласованный снимок базы, в том числе при работающем сервере, в `data/backups/`. Укажите `BACKUP_DIR` для другого каталога. Копия содержит все аккаунты и рукописи, поэтому храните её приватно вне диска сервера. При восстановлении остановите сервер, замените базу снимком, уберите старые `-wal`/`-shm` файлы этой базы и запустите сервер. Не копируйте один `.sqlite` файл работающей базы вручную: изменения могут находиться в WAL.

## API и проверки

Контракт: [OpenAPI](docs/api/openapi.json), [пояснения](docs/api/contract.md). OpenAPI можно импортировать в Postman. Установленный Postman CLI в текущей среде не найден; запуск Postman и публикация workspace не выполнялись.

```sh
npm run check
npm test
```

Тесты выполняют реальные обработчики Request/Response с временной SQLite: регистрация, вход, выход, срок сессии, изоляция аккаунтов, CSRF/Origin, ограничения данных, конкурирующие записи, сохранность после перезапуска и лимиты авторизации. Отдельно проверяются очередь сохранения, повторы после сетевого сбоя, модель рукописи и резервные копии. Это проверки в процессе Node, а не через TCP или браузер.

## Fly.io

Развёртывание на `book.ayudenko.by` подготовлено в `Dockerfile` и `fly.toml`: один экземпляр, SQLite на постоянном диске, HTTPS и health check. [Порядок деплоя, DNS и резервного копирования](docs/deploy-fly.md).

`npm run deploy` использует удалённую сборку Fly.io и отключает создание дополнительного экземпляра. `npm run smoke` проверяет уже опубликованный домен без изменения данных. Развёртывание из текущей среды пока не выполнено из-за ограничений доступа к Fly CLI.
